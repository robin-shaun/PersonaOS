# PersonaOS 0.11.0：可负责任的开源发布基线

0.11.0 把已经能运行的数字分身 MVP 变成一个可以被外部开发者理解、复现和审查
的源代码发布候选。它没有增加“更像某个人”的宣传能力，而是补齐许可证、真实
边界、依赖与容器锁定、自动 CI、API/Skill 文档和社区安全入口。

本文件是版本发布说明，不代表仓库已经创建 Git tag 或 GitHub Release，也不代表
完成生产安全认证。

## 可以演示什么

在一台有 Docker Compose 的普通 Linux 开发机上：

1. 创建一个明确标为模拟对象的人物；
2. 导入一份虚构 UTF-8 文本，原文作为 AES-256-GCM Blob 保存；
3. Worker 生成带文件、chunk、字符和行号定位的候选；
4. 用户逐条确认、修订确认或拒绝，候选不会自动写入长期记忆；
5. confirmed 当前版本进入指定 embedding 空间；
6. 词法、向量和 RRF 召回生成 evidence-only 回答；
7. citation 解析到不可变 MemoryVersion、Evidence 和原始文件；
8. 用户查看版本/关系/审计，导出或执行带依赖回执的删除。

默认流程不需要 API Key，不调用付费服务。项目维护数字员工仍可只读 GitHub
仓库，生成有证据的简报与 Issue 建议，并在交付前等待人工审批。

## 发布工程

- 许可证：Apache-2.0，附 NOTICE；
- 后端：Python 3.11.15，production/dev requirements 都精确版本并带 PyPI
  SHA-256 hash；
- 前端：Node 22.23.1，npm lockfile v3，全部直接依赖精确版本；
- 容器：Python、Node、Nginx、PostgreSQL/pgvector 保留可读 tag 并固定 digest；
- CI：Action 固定完整 SHA，默认 `contents: read`，无写仓库权限；
- 门禁：Ruff、62 项 Python 测试、Vitest、严格 TypeScript、Vite build、npm/pip
  audit、SQLite migration、PostgreSQL offline SQL、OpenAPI drift、release
  consistency 和真实 Compose smoke；
- 更新：Dependabot 分别跟踪 Python、npm、两个 Dockerfile 和 Actions。

## 从 0.10.0 升级

0.11.0 没有数据库 schema migration。升级前仍应把数据库、加密 Blob 和 Blob
密钥作为一个一致备份保存，然后：

~~~bash
git pull --ff-only
docker compose build --pull
docker compose up --detach --wait
python3 examples/compose_smoke.py
~~~

主机 SQLite 模式运行 `./start.sh --install`，会按新的 `requirements.lock`
安装。由于项目安装现在禁用 build isolation，锁文件同时包含固定 setuptools 和
wheel。不要只复制数据库而丢失 Blob 或密钥。

0.11.0 的 Compose image 名从 `personaos:0.10.0` 和
`personaos-web:0.10.0` 更新为 0.11.0，本地构建会产生新 image，但继续挂载原有
named volumes。普通停止使用 `docker compose down`；`down -v` 会删除本地人物
数据。

## 真实性和安全限制

- PersonaOS 不声称自己是现实中的本人，不上传意识、不复活逝者；
- `source_verified` 只表示文本可定位回资料，不表示资料陈述在客观世界为真；
- 用户修订会成为 `user_asserted` 新版本，不会回写或篡改原始证据；
- 当前没有认证和可信远程租户，只能本机单所有者运行；
- 原始 Blob 加密，但 chunk、候选、记忆和引用摘录仍需依赖数据库/卷加密；
- 应用删除不等于备份或物理介质净化；
- 默认特征哈希 embedding 与 evidence-only 回答器只用于免费闭环和边界验证；
- Skill manifest 不是沙箱，当前只运行仓库内受信代码；
- ASR、TTS 和数字人渲染未实现；未来运行时仍可能持续消耗 GPU。

下一步不会直接扩张人格模仿，而是 M6：可信本地账户与人物空间隔离。详见
[路线图](../../ROADMAP.md)。
