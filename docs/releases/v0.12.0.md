# PersonaOS 0.12.0：可信本地账户与人物空间隔离

0.12.0 把 0.11 的服务端固定 `local-user` 演示边界升级为可测试的本地账户闭环。
浏览器不再提交可信 owner；API 从可撤销会话派生 actor，应用仓储和 PostgreSQL
RLS 共同隔离人物、资料、记忆、检索、引用、任务、偏好、连接、导出和审计。

这仍是本地优先 Alpha，不是公网身份平台或高对抗 SaaS 多租户。Compose 默认端口
继续只绑定 `127.0.0.1`。

## 主要变化

- 受信主机 CLI 创建首个管理员和后续账户，密码不接受 argv/env 输入；
- Argon2id 密码摘要、统一失败响应、临时锁定和安全认证事件；
- 256-bit opaque Cookie，会话摘要持久化，空闲/绝对过期、即时注销与轮换；
- HttpOnly、SameSite=Strict、会话绑定 CSRF、Origin 校验；
- 高风险操作的近期再认证与 `428 reauthentication_required`；
- 严格 request schema，旧 `user_id` / `requested_by` 伪造输入返回 `422`；
- 每个 API 可达领域按会话 owner 过滤，跨账户资源统一返回 `404`；
- PostgreSQL `USING` + `WITH CHECK`、`ENABLE` + `FORCE ROW LEVEL SECURITY`；
- Web 首次初始化说明、登录、会话信息、再认证和管理员账户创建；
- 显式 legacy owner 迁移预览、冲突拒绝、精确回执与原子回滚。

## 首次安装

~~~bash
docker compose up --build --detach --wait
docker compose exec api \
  python -m apps.admin create-account \
  --username admin --display-name Administrator --role admin
~~~

第二条命令会无回显提示输入和确认至少 15 字符的密码。之后打开
http://127.0.0.1:18111 登录。首个管理员没有匿名 HTTP 创建入口。

## 从 0.11 升级

升级前同时备份：

1. 数据库；
2. 加密 Blob 目录；
3. Blob key；
4. 新生成后的 authentication key。

`alembic upgrade head` 只增加账户、会话、认证审计、迁移回执和 RLS，不改变旧
业务行的 owner。创建目标管理员后先预览：

~~~bash
python -m apps.admin migrate-legacy-owner \
  --source local-user --to admin
~~~

确认逐表计数、`conflicts` 为空、`nonterminal_task_ids` 为空且
`can_apply=true` 后，才执行：

~~~bash
python -m apps.admin migrate-legacy-owner \
  --source local-user --to admin --apply
~~~

保存输出的 `receipt_id`。如果回执列出的行没有被继续改变归属，可以回滚：

~~~bash
python -m apps.admin rollback-legacy-owner --receipt RECEIPT_ID
~~~

回滚要求所有精确主键仍属于目标账户；任一行发生分歧时，整个事务失败，不做部分
恢复。正在执行的任务或目标账户已有唯一键冲突时，apply 也会在写入前拒绝。

## 验证边界

自动化测试覆盖：

- 登录时替换现有 Cookie、再认证轮换 Cookie/CSRF、注销和过期撤销；
- 缺失/错误 CSRF、跨 Origin、无效 Cookie、临时锁定和审计脱敏；
- 两个账户各自完成资料 → 候选 → 确认 → 检索/回答 → citation → 原文导出；
- 双向探测人物、资料、记忆、任务、会话、citation、审计、导出与删除；
- legacy preview/apply/冲突/非终态任务/rollback/分歧原子失败；
- SQLite upgrade/check/downgrade 和 PostgreSQL migration SQL；
- CI 中真实 PostgreSQL/Worker/API/Nginx 双账户 Web-origin smoke；
- CI 中数据库级 RLS 默认拒绝、跨 owner 主键读取/更新/插入。

## 已知限制

- 只有密码单因素和账户级临时锁定，没有 MFA、WebAuthn、集中限流或自助恢复；
- 0.12 管理员可以创建/列出账户，但尚无账户停用、密码修改和恢复 endpoint；
- Compose migration/runtime 共用数据库角色，应用可以显式设置 system GUC；
  RLS 用于捕获仓储漏过滤，不抵御数据库凭据失守或任意 SQL；
- SQLite 不支持 RLS，不应用于远程多账户部署；
- 主机管理员控制数据库、进程和密钥卷，因此能访问全部本地数据；
- 本版本尚未经过独立渗透测试或密码学审计。
